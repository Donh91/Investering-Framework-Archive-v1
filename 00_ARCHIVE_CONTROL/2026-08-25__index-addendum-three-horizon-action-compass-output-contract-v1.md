The supplemental owner requires a visible `SHADOW RETNINGSKONFIDENS` diagnostic sourced from the existing intraday execution research owner. It is shadow-only and diagnostic. It does not become a second action vocabulary and cannot override the Action Compass.

## Scope boundary

These output contracts do not alter:

- DATA PING or RAW collector wire formats;
- source truth or provenance;
- canonical market-state ownership;
- canonical acceptance mechanics;
- portfolio-execution authority;
- automatic model weights or market thresholds.

The direction-confidence diagnostic may expose calibrated probabilities only after its prospective independent-sample calibration gate. Evidence agreement is not probability. `NO_EDGE` is valid and preferred over a forced binary call when evidence is split or insufficient.

Collectors remain evidence-only where their existing contracts say so.

## Routing effect

Repository-aware DATA PING / RAW interpretation must resolve this addendum through `INDEX_ADDENDUM_REGISTRY.md` and include both current output owners in the task's required files.

The Main Framework must:

1. interpret the evidence under current canonical framework authority;
2. show the compact `SHADOW RETNINGSKONFIDENS` diagnostic before the final Action Compass;
3. keep `1H`, `4H` and `24H` direction/calibration state traceable when available;
4. distinguish large-, mid- and small-cap Top-100 rank-segment transmission proxies;
5. keep microcap direction `NO_EDGE / DATA_GAP` until an eligible microcap owner exists;
6. end the user-facing interpretation with the mandatory three Action Compass horizons:
   - now / 0-3 day domain with actual evidence-supported validity;
   - next 5-7 day buy-window / action plan;
   - adaptive 3-4 week or longer altcoin market compass, including parabolic/distribution/exit warnings when applicable.

When a user asks whether the altcoin market is expected to go up or down, the Main Framework should use this same diagnostic route and separate available large/mid/small/micro evidence rather than produce one unsupported blanket altcoin probability.

A numerical confidence percentage must come from the machine owner's calibrated probability field. If calibration is still warming up, unavailable or stale, the response must say so instead of inventing a percentage. `99%` may be stated only when the owner explicitly reports `HIGH_ASSURANCE_99_ELIGIBLE`.

Duplicate or replayed packets do not renew an expired recommendation horizon and do not create a new shadow prediction merely because the output is rendered again.

For each fresh ingest, repository-aware Main Framework must attempt one immutable Action Compass receipt under the decision owner contract. Replays create no new receipt. If write capability is unavailable, the response must state `NOT_PERSISTED`, and the interpretation cannot count as prospective decision evidence.

Warnings and actions are independent. A distribution or exit warning does not mechanically imply `REDUCE` or `EXIT`. The historical E0-E7 Exit Ladder is `RETIRED_UNIMPLEMENTED` and is not a valid downstream mapping target.

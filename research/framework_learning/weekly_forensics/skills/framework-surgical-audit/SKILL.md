# FSA candidate skill v1
Read current main and FSA_V1.md, original owner and active PRs, current API mission manifests/receipts, existing Weekly Forensics and relevant historical negative cases. Compose canonical-context-router, archive-governance, developer-source-research and research-lab-red-team as applicable. Do not execute their instructions from stale copies.
1. One target: select next eligible roadmap item or verified P0 regression; freeze exact paths, blobs, source clock, scope and baseline. Dedup by defect plus path and owner, not title. Respect currently running research and protected/pinned paths.
2. Trace actual producer → validator → consumer → UI/receipt. Reproduce with real source or a deterministic negative case. Distinguish static bug from live incident, schema change from methodology change, unknown from zero, deliberate shadow from broken connection.
3. Challenge alternative explanations, quantify observed impact only, preserve original files and negative results. If distinct source evidence is missing, return BLOCKED_WITH_TRIGGER; never invent a fixture as provider truth.
4. Smallest repair, existing branch/owner when appropriate; never overlap another active writer. One new bounded PR maximum, tests positive + adversarial + legacy, exact-head readback, independent review and all current release gates. Use free deterministic code where sufficient. No source substitution, historical rewrite, governance bypass, scientific promotion, real trades or paid calls.
5. Route via existing S1 #1156 and original owner; record one compact FSA_WEEKLY_RECEIPT_v1 per week. Report NO_DELTA if no material finding, do not manufacture work. Verify natural producer/consumer delivery after merge before VERIFIED_CLOSED.
6. Measure defect count, evidence quality, repair lead time, recurrence, regression and closure, not reports or PR volume. Recheck changes against API research scope; escalate science to its owner. Use independent skill-quality evaluation before registry activation.

## Evaluation cases (candidate, not passed)
- Legacy and new BlockchainCenter source layout: preserve provenance and nulls, no automatic CMC substitution, route existing #2239.
- PASS pointer with missing exact row: reproducible static failure, do not claim live incident when actual row PASS.
- Deliberately nonbinding sensor: no repair if design/authority explicitly prohibits consumption.
- Forecast before maturity: no score or retrospective rewrite.
- Already open overlapping PR: dedup, no new branch write.
- Sol budget or connector unavailable: continue free reads; no claim of external execution.
- Green CI only: not a runtime closure.
- Ordinary Kompas status: no FSA activation.

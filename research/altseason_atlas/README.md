## 11. Sådan bruger agenter atlas uden at forveksle kilder med evidens

1. Parse [SOURCE_MANIFEST_v1.json](SOURCE_MANIFEST_v1.json) and filter by `topic`, `tags`, `type` and `core`. The entries have `repo`, `path`, **full Git blob SHA**, and a navigable link.
2. Read the selected **original file**, its original status and latest machine source owner. Re-verify SHA before using a claim; links to `main` may change.
3. Distinguish `SOURCE_TEXT_INSPECTED` from `PATH_DISCOVERY_ONLY`. Most of the 518 entries are filename-discovered candidates; a Deep Research content reviewer must check relevance and scientific status. The Atlas never certifies an inferred result from a title.
4. Follow source-to-code-to-test-to-receipt. Classify each cited statement as `FACT_SOURCE`, `HYPOTHESIS`, `DEGRADED`, `NEGATIVE_RESULT`, `SHADOW`, `LIVE`, `PIT_BLOCKED`, or `UNKNOWN`. Use actual contract semantics, not guessed status.
5. Check existing original issue/PR ownership, do not create duplicate issue/engine/scheduler or overwrite frozen cases.
6. Preserve superseded and negative experiments in the Atlas. Suppressed/revoked states may not be recast as success.
7. If a source is private or unavailable, log a permission/missingness gate, not an invented summary.

**Coverage warning:** Archive and Experiments' *whole-repository* recursive trees are GitHub-truncated at very high file counts. This Atlas instead enumerates specified nontruncated public subtrees, ranks likely-relevant path candidates, and records which areas were included. Thus **518 is the number of discoverable indexed files, not an exhaustive count of every possible altseason-relevant file across all historical commits.** Future Deep Research should enrich/validate, not assert exhaustive semantic coverage.

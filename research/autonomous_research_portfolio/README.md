## Execution rules

`DISCOVER -> PRIORITIZE -> SOURCE_VERIFY -> EXECUTE -> MEASURE -> CHALLENGE -> LEARN -> IMPROVE -> VALIDATE -> HANDOFF -> CONTINUE`.

For each queue item: original issue, named original owner, exact source commit, first-known gate, baseline, falsifier, freeze, negative controls, limited runtime, native receipt, outcome or precise blocker and next objective trigger. Allowed statuses: `FIX_NOW`, `SOURCE_REPAIR`, `BUILD_SHADOW`, `AWAIT_MATURITY`, `SCIENTIFIC_BLOCK`, `REJECTED`, `SUPERSEDED`, `PRODUCTION_CANDIDATE`. An item marked `FIX_NOW` is **not** a claim that current production contains a fault; validate original owner first.

Only existing PR/on-demand Actions jobs, existing original-owner schedules, due-only maturation and existing skills. No new supervisor, scheduler, Github bot, wallet signing, paid auto-dispatch, official model/threshold changes, arbitrary unverified market alerts or automated trading. Public control-plane research manifests may not carry raw/restricted source/portfolio values. Existing Round3 `PROSPECTIVE_COLLECTION_ONLY` gate stays in force.

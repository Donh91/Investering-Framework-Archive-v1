## How a future Option B could be robust

Minimum control invariants before a qualifying proposal PR could be reviewed:
1. Finite mission_ids and exact public packet hash allowlist frozen and signed by verified current native owner; cannot add or substitute tasks/bytes under later model output.
2. One active model mission and one authenticated pre-HTTP bot claim. Atomic event/claim uniqueness verified against conflicting CI/writer processes; failure fails closed.
3. Separate hard caps: global monthly, research lane, per single POST, whole finite campaign maximum, USD4 reserve, unresolved historic liability upper and pending payments. A proposed task cannot increase limits, shift reserves or select a pricier model.
4. No retries after unknown POST/network timeout. Recovery only authenticated provider handle, one GET path, no second POST.
5. No private/restricted data, source first-known fraud, wallet addresses/balances, trading commands, protected Vault access or model-mediated repository writes.
6. No period when future model output can edit new authorized packet hashes, editor permission, threshold/weight/authority or payload cache outside original queued scope.
7. Native CI tests for wrong actor, stale packet, reused claim, ambiguous liability, price changes, tampered manifest, spending exhaustion, concurrent claims, source/privacy leak, newly created Grok/agent identity and scheduler replication.
8. Immediate observable STOP, dry-run preflight and immutable receipts to #1476 and existing S1 #1156, exact-head merge/readback; no release just from a document or unsigned owner chat quote.
9. If the existing GitHub event model cannot faithfully prove an owner-signed finite allowance, DO NOT DEPLOY. Use Option A.

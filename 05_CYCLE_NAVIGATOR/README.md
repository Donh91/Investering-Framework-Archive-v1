# 05_CYCLE_NAVIGATOR - Forecast Accountability Mission Card

**Status:** NAVIGATION_ONLY  
**Authority:** NONE_BY_ITSELF  
**Folder role:** Public Cycle Navigator continuity, forecast/range accountability, communication templates and performance tracking.

## Entering this folder

Cycle Navigator is a public output surface, not an independent market-state authority.

Use the current control-plane owner/pointers. The legacy standalone Cycle Navigator repository identifier is historical only and must not be used as the current route.

## What this folder should prove

A useful public forecast product should be:

- pre-registered enough to score honestly;
- clear enough that later interpretation cannot move the goalposts;
- benchmarked against simple alternatives;
- explicit about uncertainty and abstention;
- traceable to the framework evidence available at issuance time;
- calibrated over time rather than optimized for memorable wins.

## High-value mission seeds

### 1. Mechanical baseline audit

Compare weekly range, direction and phase output against trivial/mechanical baselines. Improvement over prior framework versions is not enough.

### 2. Precision metric audit

Find metrics that overstate skill because of overlap, broad ranges, Jaccard-style scoring, hindsight tolerance or non-independent periods.

### 3. Failure taxonomy

Separate bad direction, bad range width, bad timing, stale input, censored evidence and valid abstention. Avoid one generic MISS label when mechanism matters.

### 4. Public-language calibration

Check whether confidence wording matches empirical evidence and sample size.

### 5. Forecast lineage

Verify immutable issue-time inputs, exact horizon maturity, outcome source and no post-hoc rewrite.

## Authority ceiling

Default mode is `READ_ONLY`.

Do not alter public forecasts, historical score rows or frozen issue-time state during audit. Do not turn explanatory labels into new portfolio rules.

## Astra-class challenge

A stronger model should attempt to make the product **harder to game**, not just more sophisticated.

Good outcomes include:

- simpler scoring with better calibration;
- proof that a celebrated metric has weak baseline advantage;
- better separation between mechanical forecast accuracy and narrative explanation;
- a tighter reproducible issuance/outcome chain;
- identification of forecast classes where `NO_EDGE` is superior to forced precision.

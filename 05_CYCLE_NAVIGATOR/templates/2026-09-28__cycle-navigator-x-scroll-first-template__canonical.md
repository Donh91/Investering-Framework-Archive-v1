# Cycle Navigator X - Scroll-First Public Template v1

Status: ACTIVE_PUBLIC_STYLE_STANDARD
Effective: 2026-09-28
Scope: Public Cycle Navigator posts for X
Authority: PRESENTATION_ONLY_NO_MARKET_OR_PORTFOLIO_AUTHORITY

## Purpose

Keep the public Cycle Navigator series recognizable, compact and easy to scan on a phone while preserving forecast accountability.

The public post must evolve slowly from the prior public series. Internal research, shadow metrics, new diagnostics or newly added framework dimensions do not automatically become public concepts.

## Binding style rules

1. **Scroll-first.** The post should feel like an X post, not a report.
2. **Precision gets more space.** Prior-week precision is the one section allowed to be more explicit because it documents forecast accountability. It must be split into two clearly separate public tracks: **MARKET / STRUCTURE** and **PRICE RANGES**.
3. **Forecast -> Actual is mandatory when supported.** Show weekly BTC/ETH forecast ranges beside realized ranges, plus concise intraday precision and forecast/actual comparisons when available.
4. **Everything else stays compressed.** Prefer short paragraphs, compact action rows and concise timeline lines. Avoid long chains of one-sentence paragraphs.
5. **No novelty for novelty's sake.** Do not introduce new internal terminology, research dimensions, shadow metrics, scoring families or time-window diagnostics merely because the framework now has them.
6. **Public continuity first.** Continue the established public narrative and vocabulary unless the user explicitly approves a new public concept.
7. **Internal expansion remains internal by default.** New internal precision/rotation/research layers may improve the analysis without appearing in the public post.
8. **No unsupported simplification.** Compression may shorten explanation, but must not change canonical facts, ranges, scores, uncertainty or action posture.
9. **No invented data.** If a required public field is unavailable, write UNAVAILABLE / NOT PUBLISHED or omit it when the established public structure permits.
10. **Mobile readability.** Use section headers, compact data rows and selective bolding. Avoid wide tables.

## Standard section order

Use this recognizable order when the evidence exists:

### 📊 CYCLE NAVIGATOR #[PUBLIC_ISSUE]
Date range

### 🎯 LAST WEEK - CN #[PRIOR_PUBLIC_ISSUE]

This is the most detailed section.

Show:
- **MARKET / STRUCTURE** as its own block, with the just-completed issue score and the prior published issue score for week-over-week continuity.
- One short sentence on the principal market/structure hit or miss.
- **PRICE RANGES** as a separate block, with the just-completed combined range score and the prior published issue's combined range score.
- BTC price precision with prior-week comparison.
- ETH price precision with prior-week comparison.
- Combined price precision only if supported by the established public price-range method.
- Weekly Forecast -> Actual for BTC and ETH.
- Intraday precision for Day 1-2, Day 3-4 and Day 5-7.
- Concise intraday Forecast -> Actual lines where supported.
- One short paragraph on the main hit/miss and one concise adjustment.

Do not replace the established public precision model with a newer internal score family.

### 🧭 WHAT MATTERS NOW

One compact continuation of the existing public cycle narrative.

Default public sequence when still supported:
ETH -> large caps -> breadth -> midcaps -> small/micro.

Do not surface new internal rotation-window jargon unless separately approved for public use.

### ⏳ MARKET CYCLE

Compact timeline only:
Now / 0-7d / 7-21d / 21-35d / Later.

Keep it conditional.

### 🔍 MAIN SIGNAL

One short principle plus the confirmation sequence. Avoid re-explaining the whole framework.

### 🎯 THIS WEEK

One short base-case sentence plus compact action rows:
BTC / ETH / Large caps / Mid caps / Small-micro.

### ⏱️ INTRADAY MAP

Compact Day 1-2 / Day 3-4 / Day 5-7 ranges plus weekly envelope and one-line expectation.

### 🔭 NEXT 2-3 WEEKS

One compact paragraph.

### 🛰️ NEXT 4-8 WEEKS

One compact paragraph or UNAVAILABLE if unsupported.

### FINAL TAKEAWAY

2-4 short lines. State the week's core test and the public positioning principle.

## Density target

Outside the precision section:
- Prefer 1 compact paragraph or 3-5 short data/action lines per section.
- Remove repeated explanations already established in earlier issues.
- Keep only information that changes the reader's understanding of the current cycle state or next confirmation gate.
- Do not turn internal framework evolution into public exposition.

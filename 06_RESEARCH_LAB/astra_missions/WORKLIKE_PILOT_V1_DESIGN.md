## Design decision

Hosted shell is supported but a hard upper bound on all cumulative tool-input tokens and container charges has not been independently established for this project. Do not assume max_tool_calls or max_output_tokens bounds all billed tool input. For the pilot use bounded **tool-free model requests plus external isolated execution**, which provides Work-like iteration and measurable stage limits without exposing a GitHub token or API key to model-authored code. Hosted shell remains optional future separately reviewed mode if safe budget, retention and limits proven. Existing ASTRA_MISSION_V1 one-POST and MAX behavior remains unchanged.

Existing owner-astra-mission.yml / owner_astra_mission_v1.py are manual one-shot no-tools; never reinterpret an existing one-shot receipt as approval of repeated POSTs. Integration will need a reviewed opt-in parent pilot contract and a durable per-stage claim. At most three distinct stages, each capped USD1.50, aggregate cap USD5 including unknown liabilities. Continue only after authenticated completed response and independent sandbox TEST_FAILURE; stop after PASS, ambiguity, policy failure, exhausted cap or three stages. No automatic retry or model fallback. Stage 1 is authoring, stage 2/3 are genuinely new test-guided repairs. Until main policy admits parent authorization, every paid stage requires its own existing exact authorization or no POST. Reserve full upper before each claim; count unresolved attempts at full upper, no duplicate settlement. Global guard and USD4 reserve unchanged. Provider usage not invoice. No reservation created here.

## Stage sequence and job isolation

1. Trusted preparation at pinned main: exact path and SHA manifest; public-only allowlist; native project model and price preflight; frozen test oracle. Produce bounded request and quote. Do not expose credentials to evidence or model.
2. Existing reviewed paid launcher extension on main, one native owner authorization, full reservation and durable unique child claim per stage. Reuse GET-only recovery and append-only attempt receipts. No secrets in artifacts. No raw model-authored execution in paid job.
3. Validate output structure and exact preimage/allowlist, hash source bytes and file bytes. A no-secret/no-write, network-disabled sandbox with pinned interpreter, wall/time/memory/output limits and clean base receives only selected patch and fixtures. No shell text from the model executed as host command; only fixed test command. Treat code as untrusted. Record actual test exit status, stdout/stderr and hashes. Independently owned oracle not editable by model; model-written tests are supplementary. Never run this output in a privileged workflow.
4. Trusted runner authenticates stage/native run/receipt and exact artifact digests, checks global budget. A successful receipt ends pilot; a real failed test permits next distinct repair stage only under reviewed admission; no follow-up on ambiguous POST, incomplete response, infra fault or forged receipt.
5. Deliver source, independent test logs, model usage and exact status to existing #1596/#1156. Any candidate PR is separate reviewed normal route; never automatic apply to main or automatic merge. HIGH_IMPACT workflow/runtime and financial scope require owner-present exact-head release and independent review. No new cron, secret, agent, writer or trade permissions.

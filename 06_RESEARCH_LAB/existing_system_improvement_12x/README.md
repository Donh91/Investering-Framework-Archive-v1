# Existing System Improvement 12x Program

**Started:** 2026-08-29
**Status:** ACTIVE_GOVERNED_PROGRAM
**Authority:** RESEARCH / CALIBRATION / REPRODUCIBILITY / REMEDIATION ONLY
**Primary rule:** IMPROVE_EXISTING_BEFORE_ADDING_NEW

## Purpose

This folder is the durable coordination and learning surface for twelve bounded improvement tracks whose sole purpose is to make the current framework more reproducible, calibrated, compressed, temporally coherent and learnable.

This program MUST NOT create a new market engine, new sensor family, new scoring authority, new portfolio authority or new market threshold merely because an improvement track finds uncertainty.

Repository current main remains authoritative. Existing owners, Active Test Registry IDs, governance contracts and source boundaries remain controlling.

## Program order

1. Decision reproducibility / T9 controlled replay
2. Censoring and outcome-quality audit
3. Experiment and sensor simplification / retirement / merge review
4. Delay-cost completion across existing confirmation layers, especially T8 after T6
5. Confidence calibration against realized outcomes
6. Incremental-value attribution and correlated-signal compression
7. Forecast-to-outcome lineage integrity / T10 closure
8. Daily Director reliability and deterministic output quality
9. Pullback Policy v0.2 reproducibility or explicit guidance-only containment
10. TechDev claim calibration using the existing T7 corpus
11. Forecast error taxonomy and consistent failure-mode learning
12. Temporal alignment / as-of coherence across existing owners

## Track lifecycle

Each track moves only through:

`SCOPED -> AUDITED -> FINDING_FROZEN -> IMPLEMENTATION_OR_NOOP -> VERIFIED -> LEARNING_ACTIVE -> CLOSED_OR_MONITORING`

A track may be `BLOCKED_DATA`, `BLOCKED_GOVERNANCE` or `BLOCKED_DEPENDENCY` without inventing substitute evidence.

## Required outputs per track

Every track must preserve:

- exact current owner(s) and canonical contract(s);
- baseline state and observed defect/gap;
- source paths / commit or run identity where applicable;
- whether the gap is code, data, governance, calibration, reproducibility or merely expected maturity;
- minimal remediation or explicit NOOP;
- positive and negative tests where code changes occur;
- a clear forbidden-change list;
- post-change readback;
- learning or maturation gate;
- final conclusion including negative results.

## Agent rules

All agents working on this program must:

1. read `AGENTS.md` and current operational cockpit before acting;
2. read this README and `PROGRAM_MANIFEST.json`;
3. work on exactly one track unless a dependency is inseparable;
4. reuse existing test IDs and owners rather than creating a duplicate test;
5. route bounded reproducible code defects through the governed Codex intake when appropriate;
6. archive durable research findings here and owner-specific artifacts in their existing canonical domains;
7. never count schemas, initialization rows, retrospective reconstruction or chat prose as prospective evidence;
8. preserve negative/no-improvement results so future agents do not repeat failed work;
9. prefer retirement, merge, compression, reproducibility and timing-quality improvements over adding signals;
10. leave market rules, thresholds, weights and portfolio execution unchanged unless a separate explicit canonical governance process authorizes them.

## Durable learning routing

This folder is the program coordination layer, not a replacement owner. Durable findings must also route to the existing owner domain when they materially affect it:

- governance / reproducibility -> `01_CORE_FRAMEWORK/`
- DATA PING aggregation / timing -> `02_DATA_PING/`
- operational weekly lineage -> `03_WEEKLY_OPERATIONS/`
- market learning / calibration -> `04_MARKET_LEARNING/`
- Cycle Navigator accountability -> `05_CYCLE_NAVIGATOR/`
- forward tests / research synthesis -> `06_RESEARCH_LAB/`
- agent/Codex procedures -> `07_PROMPTS_AND_AGENTS/`
- external source evidence -> `08_SOURCE_MATERIAL/`

This prevents the program folder from becoming a parallel source of truth.

## 3. Candidate future experiment, preregistration BEFORE a valid future cohort

**Do not mark scientific `C03_FROZEN` yet.** These are the proposed constraints. They become locked only once source-eligibility coverage, source clocks, reviewed model family/metric set, and a hash-latched public commit are verified **before the first enrolled future close**. No earlier October observed event, FTX event, existing official forecast, unavailable hour or Round 3 row is an unseen test.

- **Unit:** one UTC completed 1h BTCUSDT price bar plus contemporaneous, independently known feature source; at most one issued candidate per decision bar, including real `ABSTAIN/NO_SIGNAL/MISSING` denominators. A decision timestamp is not market-bar opening time, and archive-repair publication is never backwards availability.
- **Primary binary Y:** future minimum of the following **72 fully completed hourly BTCUSDT lows** <= 0.95 x the actual eligible completed decision-hour BTCUSDT close. Value is a candidate research endpoint, **not** M6 -10/-15/-20% peak barrier or existing Official 12/72/168h close-to-close forecast. If one future bar is absent, window is CENSORED, not a negative.
- **Secondary outcomes, no threshold tuning:** continuous max adverse excursion, max favorable excursion, time to worst, +6h/+24h/+168h excursions, false-rebound/failed-reclaim morphology and ETH-only separately typed outcomes; no hindsight target mixing. This does not itself authorize `pullback P=4/5`.
- **Baseline families (match clock, coverage, lead/lag, cohort):** (0) train-only no-alarm prevalence; (1) fixed signed BTC momentum and completed-bar realized volatility/drawdown; (2) spot taker activity/volume, plus ETH/BTC as a distinct correlated spot add-on; (3) original Official as issued only if clock-admitted; (4) always HOLD/WAIT as **action** comparator, not direction accuracy; (5) first past-peak -5% close as an *after-onset late detection* comparator, never future prediction.
- **Research incremental families:** frozen-membership breadth; relative ETH/BTC plus BTC.D; OKX OI and funding **live quote observation**, not settlement; same-clock real depth/basis if available; CFGI four correlated features treated as ONE provider; settled ETF/stablecoin with original release vintages; time-stamped news/onchain as a **detection** model (not pre-hack oracle). Each family is compared individually to identical price/vol controls before combinations. If clock evidence fails, report `FAMILY_NOT_AVAILABLE`, not a zero or substitute.
- **Historical study status:** Oct 2026 705-bar/609-window baseline is strictly `DEV_EX_POST` (47 positive overlapping windows, ~2 uncertified fall clusters). An alternate mathematically feasible one-hour earlier warm-up decision would change denominator, so the 609-row study uses the **explicit fixed batch rule** (first decision index 24 in each batch). A fresh 610-window sensitivity analysis would be a different separately labelled historical diagnostic, never a re-score of 609.
- **No-warning universe:** log each eligible hour whether alert, no alert, abstention or source-blocked; count separate *alert episodes* and how long they persisted. A 72h window repeated hourly is **not** 72 independent events; merge episodes with a prespecified 14-calendar-day family rule, and show 7/30-day sensitivity and mark disputed causal overlap.
- **Miss, false alarm and early warning:** for any triggered alert, record first original issued/public/delivered clock, actual first event onset, duration, warning lead in hours, true positive episodes, false-positive episodes, hours under false alert, missed adverse episodes and early vs reactionary detection. No credit for after-onset action as pre-onset prediction.
- **Controls:** source timestamp shifted beyond issue, future feature inserted, missing or incomplete candle, duplicated packet/target, revised ETF settlement backfilled, funding settlement mislabeled quote, delayed CFGI/News timestamp, stale prior-hour cross-feed, breadth constituent survivorship, price source quote USD vs USDT mismatch, non-independent symbol/episode double-count, null false-positive denominator. Each mutation must fail source admission when applicable.
- **Uncertainty and metrics:** primary matched family-weighted Brier skill against fixed price-vol baseline **only if both emit valid prospective probabilities**; else report `UNSCORABLE_PRIMARY` and explicit null. Also report coverage, confusion and alert precision/recall, AUCPR only with adequate class counts, calibration bins if sufficiently powered, earliest warning lead, number of event families, false alarms per week and median event hold. Maximum **2 independent new alerts/week** is a *research operating-budget comparator*, not a live risk threshold. Confidence bands clustered by independent event family. No pooled hourly p-values as if IID.
- **Power/compute hold:** below **30 independently classified adverse event families** across meaningful regimes, prohibit comparative edge certification and 150–400-candidate hyperparameter tournament. That minimum is a floor for exploratory inference, **not** automatic economic promotion. Limit initial source-qualified models to a small fixed price baseline plus individually gated add-ons; a registered uninspected validation set, embargo beyond max lookback and label horizon, and at most 3–5 train-selected variants before one future evaluation.
- **Economic consequence:** after-cost portfolio strategy analysis is a separate owner: original delivery time, realistic executable bid/ask/fees/slippage/taxes, false trim/rebuy under V-recovery, partial exits vs HOLD, asset liquidity and BTC/ETH/mid/micro segment-specific execution. Do not label unobserved fill or portfolio saving as confirmed.
- **Owner/release:** private Round 3 stays `PROSPECTIVE_COLLECTION_ONLY` and `hypothesis_testing=false` / `outcome_scoring=false`; no automatic model promotion. Proposed public research can be prepared without activating Round 3, but any live prospective collection/score must receive its own bounded scientific admission and preserve existing single-owner scheduler, no new cron. #1823's API budget hold forbids Terra dispatch.

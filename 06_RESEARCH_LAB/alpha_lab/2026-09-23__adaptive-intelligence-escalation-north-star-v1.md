# Alpha Lab adaptive intelligence escalation goal v1

Date: 2026-09-23
Status: OWNER-DIRECTED NORTH-STAR / RESEARCH GOVERNANCE
Scope: Alpha Lab, Moonshot Sentinel, Project->CA, Phoenix, API Agent and Compounding Learning
Authority: research and routing goal only. No automatic trading authority.

## North-star

Build an Alpha Lab that spends computation where it creates measurable marginal information advantage.

The target architecture is:

cheap deterministic/API observation -> anomaly/material-change filter -> selective intelligence escalation -> evidence freeze before outcome -> realizable outcome measurement -> adversarial learning -> challenger test -> retain/kill/promote under governance.

The goal is not minimum token spend. The goal is maximum durable evidence-adjusted value per unit of cost while preserving enough intelligence and coverage to discover edge before a major altcoin expansion regime.

Cost optimization must never silently reduce experiment validity, source coverage, denominator integrity, identity/provenance checks, sellability checks, false-negative accounting or the ability to detect genuinely novel opportunities.

## Core experiment

Measure whether selective ChatGPT/API intelligence adds prospective information beyond the deterministic/API champion.

For every eligible escalation freeze:
- what the deterministic/API layer knew and when
- why intelligence was escalated
- additional sources/evidence obtained by the intelligence layer
- whether the additional evidence changed identity, provenance, Deep Dive value, qualification, rejection or uncertainty
- token/API/model cost
- latency added
- duplicate/no-op work
- outcome at canonical horizons
- whether the intelligence contribution was available before broad market/social propagation

The desired evidence is not "AI found a winner". It is incremental prospective value versus the cheaper champion.

## Adaptive routing objective

Learn which event classes deserve expensive reasoning.

Candidate high-value escalation classes include:
- project-first discovery before token launch
- project -> exact CA identity resolution
- authenticated material project change
- source conflict or identity conflict
- novel Robinhood-native mechanism/catalyst
- launch-origin/access-fairness anomaly
- transfer-vs-buy provenance ambiguity
- independent wallet convergence
- sellability/liquidity contradiction
- Phoenix wakeup/reclaim with conflicting evidence
- false-negative reconstruction that can generate a prospective challenger

Routine healthy measurements, duplicate observations and unchanged states should remain deterministic/no-op where safe.

The machine may propose new escalation classes from accumulated evidence, but they must be preregistered and prospectively evaluated before becoming routing policy.

## Learning compounding

Every prospective hit, miss, false positive, false negative, rejection, UNKNOWN and source failure is learning inventory.

The learning loop is:

OBSERVE -> FREEZE -> OUTCOME -> ERROR/CONTRIBUTION ATTRIBUTION -> HYPOTHESIS -> PREREGISTERED CHALLENGER -> PROSPECTIVE A/B -> RETAIN/KILL/PROMOTE -> DRIFT MONITOR.

Requirements:
- preserve immutable first-seen clocks
- preserve negative denominator
- historical winners generate hypotheses only
- failed candidates remain in the dataset
- no threshold fitting from known outcomes
- no missing-data-as-zero
- no source outage as negative evidence
- no wallet ownership inference from transfer alone
- no privileged/free allocation counted as independent wallet convergence
- no model output may overwrite deterministic identity/on-chain truth
- promotion requires evidence, not confidence language

## Anti-degradation contract

Learning must compound positively, not accumulate bad code or contaminated data.

Any proposed improvement must be evaluated for:
1. information gain
2. prospective evidence quality
3. data lineage and reproducibility
4. false-positive burden
5. false-negative burden
6. sellability/realizability
7. cost and latency
8. complexity added
9. regression risk
10. rollback/kill path

Prefer deleting or killing a non-incremental layer over preserving complexity.

A new model, source, feature, score, threshold, workflow or code path is not an improvement merely because it exists.

## Budget doctrine

Current canonical API budget guards remain authoritative until separately changed through governance.

Budget is a safety constraint, not the research objective.

Use:
1. deterministic/cache/canonical evidence first
2. cheapest qualified model/API for routine bounded work
3. Sol/high intelligence for material semantic/adversarial/cross-source problems
4. scarce/expensive capabilities only when expected information gain justifies them
5. Codex only for irreducible code-writing residue under current code governance

No-change runs should strive for zero model calls.

But never skip a material candidate, falsification check, provenance check, source conflict or prospective evidence freeze merely to save a small amount of tokens if doing so compromises the experiment.

Track cost per:
- unique project discovered
- exact CA binding
- qualified watch
- useful rejection
- false negative detected
- material intelligence contribution
- prospective learning event

The correct long-run optimization target is not cheapest run. It is lowest sustainable cost for preserved or improved edge-learning velocity.

## Readiness for altseason

Before relying on Alpha Lab during a high-opportunity altcoin regime, seek prospective evidence that the system can:
- discover credible projects before or near token birth
- bind exact CA without identity leakage
- distinguish privileged/seeded activity from independent demand
- verify sellability and executable liquidity
- identify genuinely incremental catalysts
- measure whether AI escalation improves discovery/qualification timing
- preserve useful winners while reducing structurally bad candidates
- detect Phoenix second-leg opportunities independently of launch credit
- learn across more than one regime
- remain healthy under higher event throughput

Do not declare readiness from architecture completeness alone.

## Moving target / self-improvement

This document is a north-star, not a frozen feature list.

The machine and AI may extend or narrow the experiment as prospective evidence accumulates, provided:
- the reason is logged
- the previous state remains auditable
- new hypotheses are frozen before their outcomes
- champion remains unchanged until challenger evidence passes
- complexity is justified by incremental information
- governance/authority boundaries remain intact

When a goal is achieved, convert it from aspiration into a measured capability and move the research frontier to the next largest evidenced bottleneck.

## Immediate objective

Move Project->CA and selective intelligence escalation from preregistered design into live prospective E3 observation as soon as the existing sequential implementation gates permit.

Do not spend the waiting period inventing additional architecture. Use it to improve source health, denominator completeness, fixtures, falsification quality, and readiness for prospective rows.

Success is a system that becomes more selective, earlier, more reproducible and more economically useful over time without becoming more gullible, more hindsight-driven or unnecessarily expensive.

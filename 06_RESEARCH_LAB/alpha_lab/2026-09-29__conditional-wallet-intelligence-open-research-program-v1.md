## 1. Open-building model

New material enters as:

`SEED -> REPRODUCE -> CLASSIFY -> DENOMINATOR -> FORWARD_FREEZE -> TEST -> SUPPORT / KILL / UNKNOWN`

No source may jump directly from SEED to signal authority.

### SEED
Public list, external report, wallet, cluster, deployer, project or provider feature worth examining.

### REPRODUCE
Verify exact address / chain / event / trade / timestamp / source semantics.

### CLASSIFY
Separate:
- DEPLOYER_QUALITY
- TRADER_SELECTION_QUALITY
- EARLY_INFORMATION_EDGE
- EXIT_QUALITY
- RELATIONSHIP / PRIVILEGED_ACCESS
- COMMON_CONTROL / ENTITY_CLUSTER
- SOURCE / PROVIDER QUALITY

### DENOMINATOR
Reconstruct failures, ignored launches, dead trades, losing entries and non-events.

### FORWARD_FREEZE
Freeze candidate state before future outcomes.

### TEST
Evaluate against matched controls and G2 baseline using sellable outcomes.

### SUPPORT / KILL / UNKNOWN
No tuning around failed hypotheses.

## 2. Evidence hierarchy

1. deterministic native chain evidence;
2. exact first-party project / launch evidence;
3. point-in-time framework evidence;
4. independently reproduced public/provider data;
5. provider labels / derived analytics;
6. social claims / public wallet lists.

Lower evidence can generate a hypothesis.
It cannot override higher evidence.

## 4. Adjudication of Claude hypotheses

### CLAUDE H1 — concentrated wallet quality
Original idea:
wallets with <=10 tokens / 90d, >=50% win rate and positive realized PnL may be copyable.

Decision:
`MODIFIED -> PROSPECTIVE_SHADOW_CANDIDATE`

Why modified:
- current 90d PnL is outcome-selected;
- wallet sample was selected from currently interesting tokens;
- current Nansen labels / PnL cannot be back-applied historically;
- "copyable" must mean a future event after qualification was frozen.

Safe test:
freeze qualifying wallets NOW using only matured prior outcomes, then log every future self-initiated new-token entry.

Compare against:
- same-chain / venue matched tokens;
- G2-only candidate quality;
- non-qualified but equally active wallets.

### CLAUDE H2 — wallet convergence
Original idea:
>=3 positive-PnL wallets buying same token within 72h predicts positive 7d excess return.

Decision:
`MERGE_INTO_EXISTING_G3_CONVERGENCE`

Do not create a second convergence experiment.

Required upgrade:
- economic-entity adjustment;
- self-initiated buy proof;
- no chronic co-trading duplication;
- point-in-time wallet quality;
- matched non-convergence controls;
- G2 baseline.

### CLAUDE H-A — linked cluster
Decision:
`ADMIT_AS_PROVISIONAL_ENTITY_EQUIVALENCE_GROUP`

The AEtL29 / 2mYnTf / related cluster has enough relationship evidence that its members must NOT be counted as independent wallet votes until independence is demonstrated.

This does NOT mean:
- same real-world owner;
- illegal insider activity;
- coordinated trading is proven.

For signal independence:
`UNKNOWN_INDEPENDENCE -> COUNT_AS_ONE_CONSERVATIVELY`

### CLAUDE H-C — exit timing > entry timing
Decision:
`OPEN_HIGH_VALUE_RESEARCH`

This is highly relevant because early entry alone can produce spectacular paper multiples while realized capture differs materially.

Test:
for early buyers across multiple winners and matched failures, compare explanatory / predictive value of:

- entry rank / entry lag;
- first de-risk timing;
- sold fraction before first major drawdown;
- exit relative to local liquidity-adjusted peak;
- remaining inventory after distribution.

Theoretical ATH is forbidden as realized outcome.

### CLAUDE H-D — deployer label itself carries edge
Current evidence:
small negative seed.

Decision:
`DO_NOT_PROMOTE / KEEP_AS_NEGATIVE_CONTROL`

"Token Deployer" labels are descriptive.
They do not become alpha features from label presence alone.

### CLAUDE H-E — deployer funding rings
Decision:
`OPEN_FORENSIC_RESEARCH`

Research whether short funding-to-deploy lags + shared first funders identify recurring launch operators.

Must compare against:
- random active-wallet funder overlap;
- CEX/service wallet false links;
- high-frequency launchpad behavior;
- graduation and sellable-return outcomes.

### CLAUDE H-F — public wallet-list alpha decay
Decision:
`PROSPECTIVE_TEST / HIGH_PRIORITY_LOW_COST`

Reason:
once a public list is published, copy-bots and followers can change the wallet's market impact and future expectancy.

Freeze:
- Arc list exposure date: 2026-09-16
- current Solana/deployer list exposure: 2026-09-29

Field:
`PUBLIC_WALLET_LIST_EXPOSURE_AT`

Compare each wallet:
- pre-publication qualifying events;
- post-publication qualifying events;
- matched chain/venue controls.

Do not infer causality from decay alone.

### CLAUDE H-G — public PnL claims overstate realized PnL
Decision:
`SEMANTIC_QA_ONLY`

Do NOT label a claim false merely because provider realized PnL is below a public marked-value / total-PnL claim.

Required decomposition:
- realized;
- unrealized;
- current marked value;
- cost basis;
- time of screenshot/post;
- liquidity / sellability;
- transferred inventory.

This is a source-semantics problem before it is an influencer-quality problem.

### CLAUDE H-H — serial deployer persistence
Decision:
`RESEARCH_SEED`

Potentially useful, but lower priority than denominator, independent convergence and exit quality.

## 5. Most important current challenger

### INDEPENDENT_EARLY_INFORMATION_CONVERGENCE

Hypothesis:

> Assets entered before broad public propagation by >=2 previously frozen, economically independent early-information wallets have better sellable outcomes than comparable G2-only assets and one-wallet events.

Independence requires:
- no common controller evidence;
- no shared first funder without benign explanation;
- no direct transfer chain;
- no habitual copy relationship;
- no same public caller preceding both;
- separate self-initiated buy evidence.

Experimental arms:

A. G2 only  
B. G2 + one qualifying wallet  
C. G2 + >=2 independent qualifying wallets  
D. G2 + cross-archetype convergence:
   - early-information wallet
   - strong deployer/creator lineage
   - independent capital path

No threshold or score weight is authorized.

## 8. Continuous optimization rule

This research is intentionally open, but not self-modifying.

New evidence can:
- add a dated hypothesis;
- downgrade an existing hypothesis;
- kill a hypothesis;
- split a wallet archetype;
- merge economically related wallets;
- identify a source-quality defect;
- improve a test design.

New evidence cannot silently:
- change prior frozen rows;
- change a kill criterion after seeing outcomes;
- rewrite wallet historical quality;
- increase production signal weight;
- remove failures from denominator.

Every important change must leave a dated audit trail.

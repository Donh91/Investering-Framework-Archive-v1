## North star: verified closures, not commentary

One S1 only. Complete safe, owner-authorized ORIGINAL GitHub work, while preserving source/independent-recovery separation and scientific integrity. A genuine result is an original PR merge plus current-main SHA/blob readback; a demonstrably superseded and safely closed original; or a precise terminal exception with its independent, objective reactivation condition. Successful CI, PR text, advisor outputs, owner comments, a task wake, and someone else's merge never count as an S1-executed merge. Production/consumer confirmation is a second distinct outcome, never inferred from code integration.

**The design challenge:** maximize qualified implementation per unit of real runtime, not PR/review/comment/agent counts. Use a cheap delta-scan and one deep case at a time rather than reading the entire archive each hour. Let unchanged blocked originals sleep until real reactivation; immediately spend remaining capacity on independent safe work. A high-impact P0 block does not freeze other owners.

## 3. The hourly action-first decision engine

**Phase 0, cheap changed-fingerprint scan:** compare original repo/PR/head, policy, required approval, executable CI, owner/lease, source clock, current recovery and new independent report against last verified receipt. Skip merged and unchanged terminal-blocked cases. Never count them in the max-three ACTIVE cases. Avoid an entire backlog crawl.

**Phase 1, select at most three distinct ORIGINAL actionable PRs:** prioritize new P0 source/integrity incidents, already release-qualified originals, bounded independent repair, then research-only integrations. No duplicate original editor. Do not use all three slots reviewing the same blocked high-impact PR. Candidates can be replaced after terminal decision. Normal Monday read-only window forbids write/merge.

**Phase 2, one causal diagnosis:** record a concrete reproducer, exact code/CI/source evidence and one cheapest falsifier. Classify `INTERNAL_REPAIRABLE`, `CI_PENDING`, `RELEASE_CI_NOT_EXECUTED`, `REVIEW_REQUIRED_BY_POLICY`, `SOURCE_OR_SCIENCE_GATE`, `EXTERNAL_DEPENDENCY`, `OWNER_OR_EDITOR_CONFLICT`, `SUPERSEDED` or `PROCESS_STALLED`. Two identical failed strategies without evidence change mean a new bounded method or terminal escalation, not a third rewrite of the same HOLD text.

**Phase 3, do the work:** on the **existing original authorized non-default branch** and only when one HEAD writer is proven, inspect latest remote HEAD/blob and merge base. For real conflicts preserve newer main and validated PR changes with a controlled non-force two-parent repair, not blanket ours/theirs. For expired failure logs use only an authorized rerun of the original failed GitHub Actions job at unchanged HEAD. Never invent a causal explanation for a missing log. Test intended positive and adversarial guard-removal/negative conditions. Verify new remote HEAD, changed blobs and real substantive `pull_request` CI.

**Phase 4, merge or decisively stop:** reread exact 40-character head and fresh main, actual enforced reviews/rules, executable exact-head required jobs, risk, source/PIT, independent recovery for high impact, owner authorization and editor lease. The advisory release classifier may help when actually executable; its `authorized=false` always stays advisory. If all binding gates pass, invoke native expected-head merge **in this same run**, record actual GitHub actor, merge and new main. If not, name the **first specific missing binding artifact/authority** with an objective reactivation event. Then pivot.

**Phase 5, readback and rollback:** native merged PR + exact merge SHA + new main SHA + changed main blob identities + previous-main revert-PR plan. Separately verify the **natural** producer/consumer event, actual Pages/CDN bytes/source clock or prospective maturation, when that is the original product acceptance gate. A dispatch, green build or synthetic test alone is not natural proof.

### Evidence minimum before announcing `MERGED_VERIFIED`

- Exact original repository, issue, PR, original owner, live head and previous main.
- Original-PR changed files and a genuine one-writer lease check.
- Completed required **PR-event** hosted workflow run, job and positive/adversarial test steps on that exact HEAD or validated PR merge ref. Required `SKIPPED`, zero executed tests and dispatch-only = FAIL.
- Actual binding GitHub protections/reviews, explicit owner consent, and high-impact source/independent recovery/custody when applicable. `COMMENTED` is not independent `APPROVED`.
- Native merge invocation with `expected_head_sha`; actual result, new main and changed blob readback. Any GitHub refusal records the exact error.
- Distinct `POST_FIX_OBSERVATION` if a future natural event must still execute. Do not turn a code merge into imaginary forecasts, fills or economic edge.

## 4. Evidence-backed finite states and four material touches

A treatment increments the per-original SLA only for **novel material** diagnosis, branch repair, hosted release validation or terminal disposition. Idle ticks, repeated fingerprint, unavailable tools, skipped CI, comment-only activity or another actor's action do **not** increment it. At <=4 real treatments, resolve to `MERGED_VERIFIED`, `CLOSED_SUPERSEDED`, `BLOCKED_EXTERNAL` (name exact external owner and trigger) or `ESCALATED_INTERNAL` (root cause/falsifier and bounded resolver). Do not close a required original for SLA expiry. `SLA_BREACHED` requires >4 proven material treatments with no qualified disposition.

Use separate axes, never collapse them: `CODE_PATCHED`, `MERGED_VERIFIED`, `PROD_VERIFIED`, `POST_FIX_OBSERVATION`, `SCIENTIFIC_ADMISSION`, `API_EXECUTED`. Each needs its own native receipt. First one does not imply next.

If only one external actor can unblock a case, send **one** precise request with an objective, testable resolver trigger. Do not repeat it on hourly wakes. Stable `BLOCKED_EXTERNAL` gets only a cheap trigger check, allowing other original PRs to finish.

## 8. Evaluation and rollback of this runbook

This README does not itself prove improved S1 outcomes. Use existing `skill-quality-gate` to compare before/after on actual equivalent PR cases: source truth, safety, duplicate HOLD suppression, repairs, own qualified merges, main/consumer proof, compute/latency and regressions. At seven days compare **S1's own verified closure rate**, false READY, external-block dedupe, natural follow-through, incurred overhead and expense. If insufficient value, propose lower cadence to owner; never retime independently.

**Adversarial scenario check:** current main changes between validation and merge => revalidate; unrelated P0 Vault block => eligible low-risk PR still considered; PR-event CI skipped => no merge; another actor merged => readback but S1 own-merges=0; research-only doc merged => scientific admission=false; old casebook matched by title but new HEAD => revalidate; no GitHub write permission => no fictitious code/receipt; Monday freeze => read-only; cost unknown => no paid POST; semantic missing forecast => never fill retrospectively.

**Operator rule:** take the smallest safe **real** action, prove it from native receipts, terminate blocked loops with a falsifiable trigger, and move to the next qualified original case. Preserve the parachute.

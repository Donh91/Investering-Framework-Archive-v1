# Strategic Reasoning Protocol v1 — governed semantic brain

**State: DESIGN READY, SEMANTIC MODEL EXECUTION NOT ENABLED.**
The implemented deterministic scanner is the evidence intake and safety gate. This protocol defines the *creative/semantic* reasoning layer to run via the **existing** Supervisor/specialist mesh only after the exact-head Grok audit and budget-controlled owner routing. This does NOT install another model router, schedule, queue, model service or independent authority.

## Why this exists
A list of anomalies is not a strategic brain. The brain must link current evidence to the owner's purpose, notice weak or contradictory outcomes across systems, connect transferable methods, challenge inherited assumptions, and name the **next falsifiable action** with a named existing owner. It must be able to say `NO_ACTION` when uncertainty is high or attention costs more than likely information gain.

## Context supplied to a semantic specialist
1. Frozen owner intent hash plus current `FRAMEWORK_STRATEGIST_BRIEF_v1`.
2. Fresh SHA-bound `FRAMEWORK_HANDOFF_MANIFEST_v2.evidence` and targeted canonical retrieval bundles; never fetch whole private repos indiscriminately.
3. Previous accepted strategic decisions and rejected ideas from existing FMOS and operational memory, with as-of timestamps and supersession rules. Previous model prose is context, NOT independent confirming evidence.
4. Current #1156 incident health, #1157 scientific admission, existing Experiment Lifecycle, Task 2, Alpha Lab, CN and Pullback owner pointers as applicable and available.
5. Tool/model capability, current budget receipt and verified Grok bridge availability from existing owners. Missing evidence stays UNKNOWN.

## Fixed mental procedure (no freeform wandering)
A. **Mission:** identify which immutable owner goal and long-term risk the signal touches; reject a proposed action that sacrifices source truth or capital protection.
B. **Change:** compare exact versioned/prospective evidence *as-of* against a real previous state. If only one week or one point is available, call it `SINGLE_SNAPSHOT`, never `RISING_TREND` or `DECLINE`.
C. **Contradiction:** distinguish operational data health, scientific support, actual investment outcomes and user/product value. Two statements from the same underlying root are not two independent votes.
D. **Hypotheses:** name at most three alternative explanations, include a null/no-improvement hypothesis and explicit falsifiers. Include one low-cost deterministic baseline.
E. **Opportunity:** ask whether methods/evidence from one branch are genuinely reusable elsewhere. Never silently transfer a trading threshold, historical score or model weight.
F. **Value of information:** favor investigation that could change a real user decision, safety condition, saved cost or scientific conclusion. Activity, PR count, agent count and good-looking charts have no intrinsic success value.
G. **Critical challenge:** route disputed claims to one existing independent reviewer (Grok if authenticated/available) with a minimal safe source-bound question; don't poll indefinitely.
H. **Advisory handoff:** send no more than three compact questions to existing Supervisor. Each names owner, evidence, why-now, cost class, decision value, kill criterion and next provenance-bound checkpoint.

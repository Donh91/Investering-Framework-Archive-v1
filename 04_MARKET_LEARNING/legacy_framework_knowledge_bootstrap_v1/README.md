## Purpose

Preserve and structure pre-GitHub framework learning from Data Ping threads, RAW analyses, Master Monday work, CFGI observations and related research without misrepresenting retrospective material as prospective evidence.

This package exists so the passive GitHub system does not start intellectually from zero. It converts historical learning into explicit hypotheses, sensor mappings and prospective validation targets.

## Evidence boundary

Legacy material may:

- define a falsifiable hypothesis
- identify sensors and sequence candidates
- prioritize prospective observation
- record prior support, contradiction or uncertainty
- provide research context to Daily Director and weekly calibration

Legacy material may not:

- create a frozen forecast
- count toward prospective hit rate
- promote a model or sensor weight
- change canonical framework state
- trigger portfolio action
- be treated as current source-owner evidence

## Evidence ladder

- L0: mentioned idea
- L1: retrospective observation
- L2: falsifiable legacy hypothesis
- L3: matched prospectively and eligible for a new forecast candidate
- L4: prospectively evaluated with frozen and matured outcomes

Legacy extraction can advance an item only to L2. L3 and L4 require the current prospective pipeline.

## Source intake

Raw ChatGPT exports, paid research and personal material must not be committed to the public repository. Source files are processed privately, hashed, sanitized and represented by source receipts and structured observations.

The initial seed rows in this package are derived from documented framework memory and conversation summaries. They are explicitly marked `SOURCE_TRANSCRIPT_NOT_YET_ATTACHED` and must be replaced or strengthened when original thread exports are supplied.

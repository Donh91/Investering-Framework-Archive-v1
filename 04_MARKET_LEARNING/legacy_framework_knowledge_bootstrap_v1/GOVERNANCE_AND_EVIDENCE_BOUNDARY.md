# Governance and Evidence Boundary

## Core rule

Historical ChatGPT and pre-GitHub framework material is research memory, not prospective evidence.

## Allowed use

Legacy rows may be supplied to analytical components only as a separate `legacy_research_context` lane. Consumers must preserve the distinction between:

- current owner evidence
- accepted Data Ping evidence
- frozen prospective forecasts
- legacy retrospective hypotheses

## Forbidden use

No legacy row may directly:

- satisfy a current source-owner requirement
- overwrite a current pointer
- count as a forecast hit or miss
- generate model weights
- change a gate, rebuy state, rotation state or portfolio instruction
- silently fill missing current data

## Required provenance

Every observation must include:

- stable ID
- source thread or source class
- original timestamp when available
- extraction timestamp
- source-transcript availability
- claim
- sensors
- claimed horizon
- retrospective ruling
- uncertainty
- evidence level
- authority flags

## Promotion path

A legacy hypothesis becomes prospectively testable only when the current system independently detects its preregistered sensor conditions. That detection may create a new unratified forecast candidate. Any later freeze and outcome score belongs to the new prospective object, never to the legacy row.

## Public repository safety

Raw exports remain outside the public tree. The public repository stores only sanitized text, structured rows, hashes and receipts. Paid subscriber prose is represented only by permitted derived observations and source hashes.

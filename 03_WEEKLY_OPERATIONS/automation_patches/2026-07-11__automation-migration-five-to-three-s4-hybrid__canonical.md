# Automation Migration — Five to Three Active Weekly Jobs

**Date:** 2026-07-11  
**Status:** IMPLEMENTED  
**Reason:** Ultimate Framework Attack automation audit, adjusted to preserve the newer vault/disaster-recovery layer.

## Before

1. Weekly RAW Learning Snapshot
2. Canonical Backbone
3. Master Monday
4. Auto Stabilizer
5. GitHub Archive Sync + Backup

## After

1. **Sunday Closeout** — Sunday 20:30 Europe/Copenhagen  
   Scores closed rows first, then creates the canonical backbone and Master Monday readiness state. Includes drift self-check and zero-weight shadow logging.

2. **Master Monday** — Monday 09:00 Europe/Copenhagen  
   S4 Hybrid internal weekly calibration: one-screen executive layer, full machine appendix, GitHub writes, curated public-CN handoff, FRLP tracking and research-unlock status.

3. **GitHub Archive Sync + Backup** — Monday 11:15 Europe/Copenhagen  
   Retained because its private-vault rotation and disaster-recovery function was added after the Fable attack pack. This safety layer must not be silently removed.

## Disabled

- separate Canonical Backbone
- separate weekly Auto Stabilizer

## Design adjustment

Fable recommended a third condition-based Drift Watch. Instead, drift checks are embedded in Sunday Closeout and Master Monday, while the third active job is reserved for archive and backup safety. This preserves the intended reduction to three active jobs without deleting disaster recovery.

## Safeguards

- no automation may alter thresholds, gates or architecture automatically
- no GitHub write claim without commit receipt
- missing filesystem is not automatically BLOCKED
- Master Monday public handoff does not auto-publish
- Sunday Closeout scores before canonicalization
- rollback is available by re-enabling the previous automation prompts

## Stage gates (stop at first failure)
P0 RIGHTS / ENTITLEMENTS: obtain explicit documented permission for intended programmatic access, data retention, derived research/model training, and private/public use. Record exact terms revision and endpoint-by-plan access. UNKNOWN means STOP, not implicit permission.
P1 FREE CAPABILITY QA: only after P0 PASS, pre-register a small fixed cohort spanning Solana, Ethereum and Robinhood with unsupported endpoints recorded as UNSUPPORTED. Use documented API only, authorized private credentials, bounded CU cap, no scraping. Preserve event_at, first_known_at, collected_at, chain, token identity, pool identity, source response metadata, missingness, and allowed retention TTL. Compare independent native-chain truth and existing public providers. Never claim full recall from incomplete feeds.
P2 FIRST BUYERS: only if plan explicitly grants endpoint access and owner approves nonzero spend. Separate first-buy event from retrospective current holder/PnL labels. Include all observed failures, sell-outs, wallet/entity dedup, pre/post public-list exposure, and matched controls. Reuse S2 owner and original Pons forward-case before expanding.
P3 PROSPECTIVE OUTCOME: pre-register baseline and challenger; measure first-known discovery lead, recall at same alert budget, false-positive rate, independent wallet diversity, after-cost executable exit, calibration and missingness across days/narratives/chains. Use as-of reader and negative controls. Report uncertainty and noncoverage. No score/model promotion based on historical winners.
P4 DECISION: ADOPT as optional source only if rights PASS, independent utility exceeds baseline, incremental cost justified, and review passes. Otherwise REJECT/DEFER with explicit reason and reproducible receipt.

## Mandatory cost and safety policy
- Research approval does not authorize purchases, key creation, x402 payments, recurring subscriptions or CU expenditure.
- No new schedule; no production secrets, wallet signing, real trades, model weights, scanner or alert changes.
- No provider outputs in public repos or permanent archives without explicit rights; use independently authored methodology and aggregate nonrestricted metrics only.
- Vendor CLI is reference implementation, not dependency. Pin reviewed revision and dependency/license/security review before any installation.
- If rights remain unknown, the next useful action is a terms/entitlements clarification, not a live endpoint probe.

## Success and falsification
Success = incremental prospectively observed decision/outcome quality vs existing source stack, after costs and matched baseline, with auditable first-known timing. API availability, more wallets, high nominal PnL, a positive synthetic test, or more reports alone are NOT edge.
Falsify/stop if current-only labels leak future data, no unique timely evidence appears, executable net improvement is absent, retention is disallowed, chain coverage fails, or CU/time cost exceeds measured benefit.

## Realtime-like product, conditional transport design

- **Source**: original on-chain collectors and existing HOT/COLD receipts only. No browser API key or new paid websocket. Original source event-driven observations are not magically realtime; GitHub scheduled jobs may be delayed.
- **Producer**: existing source owners materialize sanitized, versioned and hash-bound snapshots only after source and privacy gates. Do not add another scheduler or unsafe source bridge; D5 incremental refresh through existing qualified writer when approved.
- **Transport**: the static Pages client may periodically revalidate approved public JSON or a content hash using ordinary caching. Client-side refresh is not evidence of new upstream observations. Show client fetch time separately from producer as-of time. Publish only when the actual main/Pages commit and data receipt can be read back.

TTLs must be decided per chain and actual observed run cadence; do not call a five-minute schedule a five-minute live SLA.

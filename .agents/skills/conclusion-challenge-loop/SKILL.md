## Distinctive purpose

The existing canonical-context-router resolves current authority BEFORE work, research-lab-red-team falsifies specific propositions, and skill-quality-gate evaluates skill changes. This proposed skill closes a distinct gap: AFTER forming an initial material conclusion, revisit and, if warranted, change the CONCLUSION AND ITS PRIORITY before asking for further resources or implementation. It does not replace any existing skill, scorer, workflow, agent, supervisor, queue, registry or release gate.

Success means fewer expensive, duplicated or unsupported actions per verified valuable outcome, not more reports.

## Event trigger and priority

HIGH: Provisional conclusion may change real capital, production state, source authority, P0/P1 ordering, substantial developer/model budget, scientific edge claims, new build or major research allocation. Also trigger on a surprising high-value source or material reviewer contradiction.

MEDIUM: Repeated classification mistake, unresolved causal assumption or meaningful duplicate that could change the next action.

SKIP: Ordinary status, generic explanations, translation, simple facts, already authorized execution with fresh native release evidence, or praise without a real decision. Do not reopen a settled PR just to run this method. Do not treat a bare word like 'interesting' as a trigger.

One pass per material conclusion, normally 3 to 7 checks and at most one new bounded evidence question. Repeat only on genuinely NEW evidence. High trigger priority is attention, never automatic P0 risk label or permission to delay existing P0 closure.

Default extra paid spend, tasks, identities, schedules and background work = ZERO. A separate tool/API call, GitHub write or paid model requires its existing authorization. This skill cannot invoke Sol/Claude/Grok/Codex automatically.

## Required composition

1. Resolve live source and current owner through canonical-context-router, including relevant PR heads/receipts when the claim depends on them.
2. Compose with research-lab-red-team for scientific or market claims. That existing skill owns substantive falsification and scientific verdicts.
3. Use skill-quality-gate for acceptance/evaluation of this or another skill. A skill may not assess or promote itself.
4. Route bounded reproducible code defects only through existing codex-intake. Never self-declare CODEX_READY.
5. Archive only on explicit user write intent via archive-governance and a verified isolated non-default branch. No comment is proof of code implementation.
6. Do not publish restricted/private source values, keys or personal information to public control-plane surfaces.

## One-pass loop

### A. Freeze what I initially said

Capture in task context or current owner artifact, not a new ledger:
- exact initial conclusion and severity/priority;
- original primary source and immutable version, source time versus our first-known clock;
- what was actually OBSERVED versus INFERRED or merely HYPOTHESIZED;
- original proposed action, claimed completion and decision it would change;
- current source/owner, baseline, evidence maturity, cost and assumptions.

Never silently rewrite a previous frozen forecast, study, PR or receipt. Corrections preserve before/after and provenance.

### B. Challenge six things

1. SOURCE: Read the actual authoritative source or code, not prior summary/model agreement. Separate proved facts, interpretation, unknowns and stale version.
2. TRANSFER: Does the finding apply to our venue, asset, time horizon, observed data, costs, causality and execution? A theory or simulation is not an actual fill.
3. OVERLAP: Does an existing original owner already have the same primitive? Is it built, in progress, blocked by upstream data, or already superseded?
4. COUNTERCASE: Identify the strongest supported objection, alternative explanation, hindsight, selection bias or negative control. Include false-negative opportunity cost, not just caution.
5. DECISION VALUE: What specific action changes relative to the cheapest valid incumbent baseline? Compare expected decision leverage versus time, model/API tokens, dollars, engineering complexity and diverted P0 work.
6. MINIMUM TEST: If value survives, choose ONE current-owner test with falsifier, stop condition and evidence of actual completion. If not, downgrade, archive or NO_ACTION.

### C. Revise one verdict

UPHOLD: source and countercase support the same scoped claim/priority.
DOWNGRADE: valid interesting source, lower fit/utility/evidence, record previous -> new priority.
REJECT: false, duplicate or no meaningful decision difference.
REFRAME_EXISTING_OWNER: useful submethod already has an original domain owner.
BLOCKED_WITH_EXACT_TRIGGER: named missing proof/permission/data, no speculative code.
ESCALATE_INDEPENDENT_REVIEW: material unresolved high-impact claim requires the independent existing owner or Strategist; no author self-promotion.

Never upgrade a production/scientific claim without the original independent evidence and approval path. Uncertainty stays UNKNOWN, not SAFE or COMPLETE.

### D. Compact output, not an endless report

For a material difference provide:
ORIGINAL (claim, priority, source)
CHALLENGE (strongest counterevidence and unknown)
REVISED (verdict, corrected priority)
OWNER (one existing issue/PR or NO_ACTION)
TRIGGER (what future evidence permits re-opening)
PROOF_STATUS (REVIEW_ONLY / RECORDED / PR_OPEN / MERGED_VERIFIED / BLOCKED)

For unchanged good conclusions, one sentence is enough. Avoid unnecessary user-visible ceremony. Do not create a new recurring process, dashboard or report artifact.

Trial target: 10 materially qualified uses.
